# Промт: fw-backup — минималистичный монитор зеркалирования папок в трее

> Готовый запрос для агента/разработчика: «Создай Windows-приложение по спецификации ниже».

Создай Windows-приложение на чистом C++ (Win32 API, без фреймворков и внешних зависимостей) — один маленький `.exe`, который висит в трее, следит за списком пар «источник → приёмник» и зеркально копирует изменения. Обязательный итог: один `.exe` ≈300–400 КБ, статически слинкованный, работающий на «голой» Windows 7+ без установки.

## 1. Ядро: зеркалирование

- Конфиг — список пар `источник|приёмник`. Приложение следит за каждым источником
  и воспроизводит изменения в приёмнике: новые/изменённые файлы копируются
  (сравнение по размеру **и** времени модификации), недостающие папки создаются,
  удаления из источника отражаются в приёмнике.
- **Debounce**: после события файла копировать не сразу, а после `DebounceMs` мс
  «тишины» на этой папке (файлы часто дописываются по частям). По умолчанию 1000 мс.
- **KeepOrphans=1**: файлы, появившиеся в приёмнике извне, НЕ трогать и НЕ удалять
  (зеркало одностороннее: источник→приёмник). При 0 — лишнее в приёмнике убирать.
- **ArchiveDeleted=1**: при удалении файла в источнике НЕ стирать копию, а
  перемещать её в папку `!src_deleted\<относительный путь>` в корне приёмника
  («!» — чтобы папка была вверху сортировки в Explorer). Коллизии имён в архиве —
  суффиксы 2..9999. Перенос внутри тома — `MoveFileW` (мгновенно); если не вышел —
  пофайловый fallback. Папки-предки в приёмнике создавать автоматически.
  Если в корне ИСТОЧНИКА заведена папка с именем `!src_deleted` — предупреждение в
  журнал (имя зарезервировано в приёмнике). Сам архив не зеркалить сам на себя.
- **SkipFullSync=1**: при старте НЕ выполнять полную сверку (полная сверка идёт
  по ручной команде «Синхронизировать сейчас» или по событиям файлов).
- Полная сверка одной пары: просканировать оба дерева в индекс
  (относительный путь → {это папка?, размер, время}), создать недостающие папки,
  скопировать новые/изменившиеся, при KeepOrphans=0 — убрать лишнее в приёмнике.
- **Исключения** (маски папок и файлов): маска, содержащая `\`, сверяется с
  относительным путём (`PathMatchSpecW`), маска без `\` — с именем файла.
  Исключённые пути не наблюдаются и не копируются.
- Защита от самоедства: пары с пустыми сторонами, `src == dst`, источник внутри
  приёмника или наоборот — молча игнорировать. В symlink/junction не заходить.
- Наблюдательная нить: на пару — `ReadDirectoryChangesW` в overlapped-режиме
  (следить за поддеревом, в буфер падает имя файла), буфер 64 КБ; изменения копятся в очередь
  «в копирование» / «на удаление», отдельная нить-исполнитель разгребает очередь
  с debounce.

## 2. Реестровая схема (HKCU\Software\FwBackup)

| Параметр | Тип | Смысл |
|---|---|---|
| Pairs | REG_MULTI_SZ | строки «источник\|приёмник»; пустые/битые строки молча пропускать |
| Excludes | REG_MULTI_SZ | маски исключений |
| DebounceMs | REG_DWORD | по умолчанию 1000, минимум 100 |
| KeepOrphans | REG_DWORD | 1 — чужие файлы приёмника сохранять |
| ArchiveDeleted | REG_DWORD | 1 — удалённое в `!src_deleted` |
| SkipFullSync | REG_DWORD | 1 — без полной сверки на старте |
| LogFile | REG_SZ | путь журнала (значение пустое — журнал выключается) |
| (автостарт) | HKCU\...\Run, значение FwBackup | путь к exe; галочка в настройках |

## 3. Трей-иконка и анимация (критичные факты о Windows)

- Иконка рисуется БЕЗ готового .ico — программным DIB: 32×32, top-down, 32bpp,
  полная альфа (0xFF), корректная монохромная маска (0 = непрозрачно; мусорная
  маска ломает отрисовку при наведении).
- **Раскадровка** (сделай функцией `MakeTrayIcon(phase)`, phase 0..3):
  - `0` покой: оранжевый фон RGB(235,140,0), белая стрелка вниз + «полка» приёмника;
  - `1..3` busy: красный фон RGB(200,35,35), та же стрелка, под ней три белые
    «бегущие точки» (по 4px, шаг 6px): старт от левого края (x=3, чуть левее
    полки), полный пробег к правому краю (последняя точка фазы 3 встаёт вровень
    с правым краем); сдвиги фаз 0 / 4 / 8 px; тик 400 мс.
- **Перекраска значка — известные грабли Windows**: `NIM_MODIFY` со старым
  (кэшированным) HICON **не перекрашивает** значок (обновляет только подсказку).
  Рабочие каналы:
  1. **основной**: `NIM_MODIFY` со СВЕЖИМ HICON каждый кадр (строится заново,
     не кэшируется) — красит без миганий и «прыжков»;
  2. аварийный: `NIM_DELETE`+`NIM_ADD` — красит гарантированно, но заметно
     мигает/прыгает; использовать только для восстановления отсутствующего значка.
- Скрытое окно приложения — ОБЫЧНОЕ невидимое верхнего уровня
  (`WS_POPUP` + `WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`), а НЕ message-only,
  иначе не приходят широковещательные сообщения оболочки (`TaskbarCreated`).
  По `TaskbarCreated` значок ставить заново.
- Подсказка: «fw-backup: пар N — активен / пауза / синхронизация» и
  обновляется отдельным лёгким `NIM_MODIFY` с NIF_TIP; страховка — лёгкий тик раз
  в 30 с (полная переустановка только если значок действительно отсутствует).
- **Анимация привязана к реальному копированию**: busy — атомарный счётчик
  (`InterlockedCompareExchange/Increment/Decrement`), который инкрементируют ВСЕ
  пути копирования (событийные копии, «Синхронизировать сейчас», пересоздание
  наблюдателей). Пока busy>0: таймер 400 мс крутит фазы 1→2→3→1; сразу при входе
  в busy показать фазу 1 (красный). После обнуления busy — анимация догорает
  2 тика (grace) и мягко возвращается в покой ТОЖЕ свежим HICON'ом (без миганий).

## 4. Диалог, меню, жизненный цикл

- Один экземпляр: именованный мьютекс `Local\FwBackupSingle`; второй запуск —
  MessageBox «уже запущен» и выход. Параметр `/settings` — открыть настройки сразу.
- Меню значка (правый/левый клик): **Настройки…**, **Синхронизировать сейчас**
  (недоступна во время копирования), **Пауза/Продолжить**, **Перечитать конфиг**
  (недоступно во время копирования), **Выход**.
- Диалог настроек (чистый Win32): многострочные поля пар и исключений, поле
  debounce, путь журнала, чекбоксы автозапуск / архив удалённого / сохранять
  чужие файлы / без полной сверки на старте; «Сохранить» пишет реестр и
  запускает перечитывание конфига в отдельном потоке (осторожно остановить
  старых наблюдателей, создать новых).
- **Выход должен быть штатным**: `PostThreadMessageW(gMainThreadId, WM_QUIT)` —
  затем остановить наблюдателей, снять значок, освободить все HICON и закрыть
  мьютекс; в журнал — «=== выход». НЕ потеряй: жёсткое убийство процесса оставляет
  в трее «призрак» — мёртвый значок (пользователю придётся гасить наведением).
- **Журнал** (`LogFile`): UTF-8, строки с меткой времени до мс; писать только
  старт («запуск, пар: N»), выход, ошибки и предупреждения — пофайловое
  копирование НЕ логировать (спам). Записи под mutex, открытие в append-режиме.

## 5. Сборка

MinGW-w64 (основной путь):
```
g++ -O2 -s -mwindows fw-backup.cpp -o fw-backup.exe -lshlwapi -static -static-libgcc -static-libstdc++
```
MSVC альтернативно: `cl /O1 /MD fw-backup.cpp /Fe:fw-backup.exe /link shlwapi.lib`.
Кодировка файла — UTF-8, UNICODE/_UNICODE определены, `_WIN32_WINNT 0x0601`.
Весь UI-текст — на русском (настройки, подсказки, журнал).

## 6. Правила реализации (чтобы не налажать)

- Никаких библиотек/фреймворков/установщиков; только Win32 + CRT + shlwapi.
- Канал отрисовки значка: см. п.3 — только `NIM_MODIFY` со свежим HICON,
  Del+Add — только восстановление. Владение HICON аккуратное: значок, стоящий
  в трее, уничтожается только когда его точно больше не показывают.
- Пауза: при паузе нити-исполнители спят на событии — копирование не идёт,
  анимация не нужна; продолжение будит их.
- Все конфиг-чтения под mutex (конфиг может перечитываться в рантайме).
- Потоки-наблюдатели умирают быстро по событию останова (никаких бесконечных
  блокировок) — от этого зависит быстрый штатный выход.

## 7. Критерии приёмки

1. Запуск: значок в трее (оранж), в журнале «запуск, пар: N».
2. Дроп файла в ИСТОЧНИК → через ~DebounceMs файл появился в приёмнике,
   значок на секунды краснел (анимация точек), затем вернулся в оранжевый.
3. Удаление файла в источнике → копия оказалась в `!src_deleted\<путь>` приёмника.
4. Дроп файла в ПРИЁМНИК → никакой реакции (KeepOrphans=1). Это НЕ поломка.
5. «Синхронизировать сейчас» на втором диске/долгой паре — заметная красная фаза
   с бегущими точками; на пустом источнике — мгновенная (короткая вспышка).
6. «Перечитать конфиг» подхватывает новые пары без перезапуска.
7. Выход из меню — штатный; в трее нет мёртвых значков.
8. Перезапуск проводника — значок восстанавливается (`TaskbarCreated`).
